## Decision

Implemented the POST /api/fork route that creates a fork of an existing agent session. The route: (1) validates five required fields (workspace_id, session_id, agent_session_id, fork_after_index, correction_prompt) returning 400 on the first missing field; (2) fetches full paginated message history using limit:200 and after_id cursor; (3) truncates at fork_after_index (inclusive) and transforms via mapMessagesForImport; (4) imports the truncated session via importClaudeSession with the original agent_session_id as claude_session_id; (5) launches a new workspace session with resume_session_id and correction prompt prefixed with re-apply instructions; (6) returns { success, fork_session_id, fork_agent_session_id }. Errors from steps 2-5 are caught and returned as 500 with the error message.

## Alternatives

- Could optimize pagination by stopping early once fork_after_index messages are fetched, but spec says fetch full history first then truncate

## Assumptions

- getAgentSessionMessages pagination uses after_id cursor with has_more flag
- importClaudeSession returns user_session_id and agent_session_id on success
- launchWorkspaceSession accepts resume_session_id to continue from imported session
